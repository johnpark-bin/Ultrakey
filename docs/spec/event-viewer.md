# F-18 · Event Viewer — 입력 → 해석 대조

> **한 줄 요약**: 사용자가 지금 누른 키의 **원본 이벤트**와 Ultrakey 가 그것을 **어떻게 해석해 무엇을 내보냈는지**를 한 줄씩 나란히 보여주는 진단 창. keycode · 수정자 · **적용된 규칙**까지 보여준다. 목적은 "내 설정이 제대로 되어 있는가"를 사용자가 스스로 판정할 수 있게 하는 것이다.
> **의존성**: `F-07`(`key-remapping-engine.md`) — 이 창이 보여주는 자료는 전부 탭 콜백이 이미 만들고 있는 것이다. `F-09`(`preferences-ui.md`) — 창을 여는 진입점이 `General` 탭에 있다. `docs/dev/architecture.md` §2.1·§2.2 — ⭐ **이 문서가 지켜야 하는 가장 강한 제약**(탭 콜백 락 없음·할당 없음).
> **1차 근거**: 사용자 원문(이슈 #39) — *"실제로 내가 지금 어떤 키를 입력했고 어떤 키가 어떻게 해석되고 있는지를 볼 수 있는 페이지 / 카라비너 이벤트뷰어처럼 아주 정교하지는 않더라도 / 최소한 내가 지금 설정이 제대로 되어 있는지 어느 정도는 확인할 수 있어야 된다"*.
> ⚠️ **원본 SuperKey 에는 이 기능이 없다.** 이것은 원본 재현이 아니라 **클론 고유의 갈라짐**이다 — [`README.md` 원본과 갈라지는 지점](README.md#-원본과-갈라지는-지점-divergence) **D8**.

## 1. 개요

### 1.1 왜 새로 만들지 않는가 — 이미 있는 자산

⭐ **이 기능에 필요한 자료는 이미 전부 수집되고 있다.** 이슈 #19(물리 caps lock 버그) 진단을 위해 PR #23 이 넣은 탭 계측(`crates/ultrakey-engine/src/trace.rs`)이 정확히 그 자료를 만든다:

| 계측이 이미 갖고 있는 것 | `TapTrace` 필드 | 이 창이 보여줄 것 |
| :--- | :--- | :--- |
| 탭에 **도착한 그대로**의 이벤트 | `raw_kind`·`raw_keycode`·`raw_flags`·`autorepeat` | 좌측 "입력" |
| D-1 alias 환원 후 판정에 쓰인 키 | `resolved_keycode`·`alias_active` | 좌측 "판정 대상" |
| 어느 계층이 결정했는가 | `layer` | 우측 "적용된 규칙" |
| 통과/변형/소비 | `disposition`·`disposition_flags` | 우측 "처리" |
| 실제로 합성해 내보낸 이벤트 | `emitted`·`emitted_len` | 우측 "출력" |
| 부수 효과(caps lock 토글 등) | `effects`·`path_c_*` | 우측 "효과" |

**결정: 새 계측을 만들지 않고 이 링 버퍼의 소비자를 하나 더 붙인다.** 기각한 대안:

- **탭 콜백에 UI 전용 계측을 새로 넣는다** — 같은 자료를 두 번 만들게 되고, 임계 경로에 코드가 하나 더 들어간다. §2 의 불변식을 지켜야 하는 지점이 둘로 늘어난다.
- **로그 파일을 tail 해서 파싱한다** — 계측이 `ULTRAKEY_TRACE_TAP` 로만 켜지고 로그는 사람이 읽는 형식이라, 켜는 방법과 파싱 규약 두 가지를 UI 가 떠안게 된다. 링 버퍼에서 직접 받으면 둘 다 없다.

### 1.2 범위

**한다**: 키보드 이벤트의 입력 ↔ 해석 대조 표시, 창을 켜고 끄는 수명주기, 지우기, 일시정지.
**하지 않는다**: 이벤트 편집·재생·주입, 마우스/스크롤 이벤트 표시(§3.6), 파일로 내보내기(로그가 이미 그 역할을 한다), Karabiner EventViewer 의 "Devices"·"Unknown Events" 탭 상당물.

## 2. ⭐ 가장 강한 제약 — 탭 콜백에 부담을 주지 않는다

`docs/dev/architecture.md` §2.2 는 콜백 안에서 **`Mutex`/`RwLock` 획득 · 힙 할당 · 파일 I/O · 동기 로깅 · Tauri `emit`** 을 금지한다. 이 창은 그 금지를 하나도 건드리지 않는다.

```
탭 스레드(콜백)          드레인 스레드(200ms)         메인 스레드(Tauri)
─────────────────       ────────────────────        ──────────────────
should_trace()          ring.pop()                  eventviewer_poll 커맨드
  = OnceLock 읽기         → ViewerRecord 로 디코드      → VecDeque 에서 꺼내 응답
  + AtomicBool(Relaxed)   (여기서 처음 할당한다)
TapTrace 조립(스택)      → 앱의 VecDeque(500)에 push
ring.push()  ← 무잠금
```

### 2.1 "뷰어가 꺼져 있을 때 비용 0" 의 정확한 의미

⭐ **정직하게 적는다: 문자 그대로의 0 은 불가능하다.** 콜백은 "기록할 것인가"를 어떻게든 물어야 하고, 그 물음의 최소 비용이 존재한다. 이 설계가 도달하는 바닥은 다음과 같다.

| 뷰어 상태 | 콜백이 추가로 하는 일 |
| :--- | :--- |
| **꺼짐** | `AtomicBool::load(Relaxed)` **한 번**. 그 외에는 아무것도 없다 — `TapTrace` 조립도, `ring.push` 도, 할당도, 분기 예측 실패를 부를 만한 것도 없다 |
| 켜짐 | 기존 `ULTRAKEY_TRACE_TAP=1` 경로와 **완전히 동일**하다(스택 위 POD 조립 + 무잠금 push) — 이미 실측으로 임계 경로에 안전함이 확인된 경로다 |

`Relaxed` 로드는 x86-64·arm64 모두에서 평범한 로드 명령 하나이고 메모리 배리어를 넣지 않는다. 뷰어를 켜고 끄는 것은 사람이 창을 여닫는 빈도이므로 `Relaxed` 로 충분하다 — 몇 개의 이벤트가 늦게 기록되기 시작하거나 늦게 멈추는 것은 진단 도구로서 아무 문제가 아니다.

⛔ **기각한 대안**: `ArcSwap<Option<Sink>>` 로 싱크 자체를 콜백이 읽게 하기 — `load_full()` 이 `Arc` 리테인(원자적 증감)을 유발하고, 꺼져 있을 때조차 그 비용을 낸다. `AtomicBool` 하나가 더 싸고, 싱크는 드레인 스레드만 보면 된다.

### 2.2 드레인 스레드는 항상 떠 있다

지금은 `trace::spawn_drain_thread` 가 `trace_enabled()`(환경변수)가 거짓이면 스레드를 만들지 않는다. 뷰어는 **실행 중에** 켜지므로 스레드가 그때 있어야 한다.

**결정: 드레인 스레드를 엔진 시작 시 항상 띄운다.** 200ms 마다 깨어나 링이 비어 있으면 즉시 다시 잠든다 — 초당 5회의 빈 깨어남이고, 그 비용은 측정 가능한 수준이 아니다. 기각한 대안:

- **뷰어를 켤 때 스레드를 만들고 끌 때 join** — 켜고 끄는 경로마다 스레드 수명 관리가 붙고, 그 사이에 엔진이 재시작되면 소유 관계가 꼬인다. 얻는 것(잠자는 스레드 하나)이 그 복잡도보다 작다.
- **콜백이 직접 채널에 보낸다** — §2 금지 목록의 "채널 `send` 의 블로킹 변형"에 걸린다. 무잠금 링이 이미 그 자리를 차지하고 있다.

## 3. 동작 명세

### 3.1 창 — 설정 창 안의 탭이 아니라 **별도 창**

⭐ **결정: `Event Viewer` 는 독립 창이다.** `General` 탭의 `Open Event Viewer` 버튼이 연다.

**근거 — 이 기능은 다른 앱에서 타이핑하면서 봐야 한다.** 설정 창 안의 탭으로 만들면 사용자가 관찰하는 동안 최전면 앱이 Ultrakey 설정 창이 된다. 그런데 사용자가 확인하고 싶은 것은 "내가 **평소 쓰는 앱에서** 키를 눌렀을 때 무엇이 나가는가"다. 별도 창이면 `NSFloatingWindowLevel` 로 항상 위에 두고, 사용자는 편집기·터미널에 포커스를 준 채 관찰할 수 있다.

부수 근거 둘:
- 이슈 #40(탭 아이콘·`Function Keys` 토글 UI 위치)이 `settings.html` 의 탭 구조를 동시에 고치고 있다. 새 탭을 넣으면 정확히 그 파일에서 충돌한다. 별도 창이면 `settings.html` 에 **버튼 한 개**만 더한다.
- 창을 닫는 것이 곧 "뷰어 끔"이라 §2.1 의 수명주기가 UI 와 1:1 로 대응한다 — 사용자가 끄는 것을 잊어 계측이 계속 도는 상태가 생기지 않는다.

⛔ **기각한 대안**: `General` 탭 안의 접이식 패널 — 위 근거 1(관찰하려면 포커스를 내줘야 한다)이 그대로 치명적이다. 자기 자신을 관찰하는 도구가 된다.

**창 속성**: 700 × 520 pt(기본), `resizable`, 항상 위(floating), 활성화되어도 키 윈도우를 빼앗지 않을 필요는 **없다**(오버레이와 달리 사용자가 스크롤·클릭해야 한다). 크기·위치는 영속하지 않는다 — 진단 창이라 세션마다 기본값에서 시작하는 편이 예측 가능하다.

### 3.2 수명주기 — 켜짐/꺼짐이 창과 묶인다

| 시점 | 동작 |
| :--- | :--- |
| `Open Event Viewer` 클릭 | 창을 만들고(이미 있으면 최전면으로) `trace::set_viewer_enabled(true)` |
| 창이 닫힘 | `trace::set_viewer_enabled(false)`, 버퍼 비움 |
| 앱 종료 | 창과 함께 사라진다 — 별도 정리 없음 |
| `Pause` 토글 | **계측은 계속 돈다**. 프런트엔드가 새 줄을 화면에 붙이지 않을 뿐이다(사용자가 방금 지나간 줄을 읽을 시간을 준다) |
| `Clear` 버튼 | 앱 쪽 버퍼와 화면을 함께 비운다 |

⚠️ **`ULTRAKEY_TRACE_TAP` 환경변수와 독립이다.** 둘 중 하나라도 켜져 있으면 계측이 돈다. 환경변수로 켜 둔 채 뷰어를 닫아도 로그 계측은 계속된다 — 그것이 그 환경변수의 계약이다.

### 3.3 한 줄이 보여주는 것

| 열 | 내용 | 원 자료 |
| :--- | :--- | :--- |
| `#` | 일련번호 | `seq` |
| `time` | 드레인 시각(HH:MM:SS.mmm) | 드레인 스레드가 찍는다 |
| **입력** | `KeyDown  0x39 caps lock  ⇧⌃` (+ `↻` autorepeat) | `raw_kind`·`raw_keycode`·`raw_flags`·`autorepeat` |
| `→` 판정 대상 | alias 가 걸렸을 때만 `0x4F f18` 을 덧붙인다 | `resolved_keycode`·`alias_active` |
| **적용된 규칙** | `Presets · Caps lock + W A S D` / `Hyperkey` / `(없음 — 통과)` | `layer` + ⭐ `rule`(§3.4) |
| **처리** | `Pass` / `Pass (flags ⌃⌥⌘⇧)` / `Consume` | `disposition`·`disposition_flags` |
| **출력** | `KeyDown 0x7E ↑` 를 최대 4개까지 | `emitted` |
| **효과** | `ToggleCapsLock (off→on)` · `OpenSeek` · `Type 'ㄱ'` | `effects`·`path_c_*` |

**소비된 이벤트는 시각적으로 구분한다** — `Consume` 인 줄은 좌측에 색 막대를 둔다. "내가 누른 것이 그대로 나갔는가, 아니면 Ultrakey 가 먹고 다른 것을 냈는가"가 이 창의 핵심 질문이기 때문이다.

### 3.4 ⭐ "적용된 규칙" — `Layer` 만으로는 부족하다

`Outcome` 은 지금 어느 **계층**이 결정했는지(`Layer`)만 들고 있다. 그런데 `Layer::PresetCombo` 하나에 F-08 프리셋 16종이 전부 들어간다 — 사용자가 "내 설정이 제대로 되어 있나"를 판정하려면 **그중 어느 것이 발화했는지**를 알아야 한다.

**결정: `Outcome` 에 `rule: Option<RuleId>` 를 더한다.** `RuleId`(`rules.rs`)는 이미 `Preset(u8)`·`Korean(u8)`·`Hyperkey` 로 규칙을 개별 식별하고 있고, 중재기는 규칙이 발화하는 순간 그 값을 손에 쥐고 있다. `RuleId` 는 2바이트 POD 라 `Outcome` 의 무할당 성질을 깨지 않는다.

- 표시 문자열은 **드레인 스레드/앱 계층**에서 만든다 — `Preset(5)` → 문자열 카탈로그의 그 프리셋 라벨. 콜백은 여전히 숫자만 다룬다.
- 규칙이 발화하지 않은 통과(`Layer::Passthrough`)는 `None` 이다.

⚠️ **이 변경은 `crates/ultrakey-core/src/arbitration.rs` 를 건드린다** — 필드 추가와 발화 지점에서의 대입뿐인 **가산적** 변경으로 한정한다. 같은 파일을 건드릴 수 있는 병렬 작업(M3-3 `feat/seek-session`)과의 병합을 쉽게 만들기 위해서다.

### 3.5 창이 열려 있는 동안의 자료 흐름

1. 드레인 스레드가 `TapTrace` 를 꺼내 `ViewerRecord`(serde 직렬화 가능한 디코드본)로 바꾼다. **여기가 첫 할당 지점이다** — 탭 스레드가 아니므로 허용된다.
2. 앱이 등록해 둔 싱크가 그것을 `Mutex<VecDeque<ViewerRecord>>`(상한 **500**)에 넣는다. 넘치면 앞에서 버린다.
3. 프런트엔드가 **100ms 주기로** `eventviewer_poll(after_seq)` 를 불러 새 레코드만 받아 붙인다.

⛔ **기각한 대안 — `emit` 으로 밀기**: 키를 빠르게 치면 이벤트가 초당 수십 건이고, 그때마다 IPC 메시지를 하나씩 보내면 WebView 가 렌더보다 메시지를 더 많이 받는다. 폴링이면 한 번에 묶여 오고, 창이 백그라운드일 때 자연스럽게 느려진다.

**왜 500 인가**: 화면에 실제로 보이는 것은 수십 줄이고, 사용자가 되돌아보는 범위는 "방금 누른 몇 번"이다. 500 줄이면 빠른 타이핑 기준 10초 이상을 덮는다. 무한히 쌓으면 진단 창을 열어 둔 채 하루를 보내는 사용자에게 메모리 누수가 된다.

### 3.6 마우스 이벤트는 보여주지 않는다

`ULTRAKEY_TRACE_TAP=all` 과 달리 뷰어는 **키보드 이벤트만** 기록한다(`should_trace` 의 `KeysOnly` 와 같은 판정). 근거는 계측 자체가 이미 실측으로 얻은 교훈이다(`trace.rs` 모듈 문서): 마우스를 조금만 움직여도 `MouseMoved` 가 초당 수백 건씩 쌓여 **정작 봐야 할 키 이벤트가 파묻힌다.** 이 창의 목적은 키 설정 확인이다.

## 5. 엣지 케이스와 실패 모드

1. **권한이 없어 탭이 없다.** 계측할 이벤트 자체가 없다. 창은 열리되 "Accessibility 권한이 없어 이벤트를 관찰할 수 없다"는 안내를 보여준다(F-11 의 온보딩으로 유도).
2. **엔진이 아직 시작되지 않았다.** 위와 같은 처리 — 창은 열리고, 이벤트가 오면 그때부터 채워진다.
3. **링 오버플로.** 무잠금 링은 가득 차면 조용히 버린다(기존 동작). 뷰어는 `dropped_count` 를 읽어 사용자에게 알린다(§4).
4. **창을 닫는 순간의 잔여 레코드.** 드레인 스레드가 이미 꺼낸 것이 버퍼에 남아 있을 수 있다 — 창을 닫을 때 버퍼를 비우므로 다음에 열면 깨끗하다.
5. **Secure Input 이 켜져 있다.** 콜백이 계층 0 에서 상태를 리셋하고 통과시키므로(§2.3 진입 순서 0-d) 뷰어에도 `Pass` 로 보인다. 이것은 오류가 아니라 사실이며, 사용자가 "왜 암호 입력창에서는 리매핑이 안 되는가"를 스스로 확인하는 경로가 된다.
6. **앱별 비활성화(`Ignore <앱>`)가 걸려 있다.** 계층 0 문지기가 통과시키므로 `Layer::AppGate` + `Pass` 로 보인다 — ⭐ 이것이 이 창의 가장 유용한 진단 중 하나다("설정이 안 먹는데?" → "이 앱이 무시 목록에 있다").
7. **자기 합성 이벤트.** 마커가 붙은 이벤트는 콜백이 계측 전에 통과시키므로 뷰어에 나타나지 않는다. 나타나면 그것 자체가 버그의 증거다.

---

## 6. 필요한 플랫폼 API

**없다.** 이 기능은 이미 있는 자료의 소비자를 하나 더 붙이는 것이고, 새 창은 Tauri `WebviewWindowBuilder` 로 만든다. 항상 위 속성만 `ultrakey-platform` 의 기존 `ns_window()` 경유 설정을 재사용한다(F-03 이 이미 쓰는 경로).

## 7. 구현 접근 분류

**순수 Rust + 기존 Tauri 배선.** 새 `unsafe` 없음, 새 프레임워크 링크 없음, 새 크레이트 없음.

## 8. 수용 기준

- [ ] `General` 탭에 `Open Event Viewer` 가 있고, 누르면 별도 창이 뜬다.
- [ ] 창이 **닫혀 있는 동안** 탭 콜백이 하는 추가 작업은 `AtomicBool` 로드 하나뿐이다 — `TapTrace` 조립도 `ring.push` 도 일어나지 않는다(단위 테스트로 검증: 뷰어 off + 환경변수 off 에서 `should_trace()` 가 거짓).
- [ ] 창이 열려 있을 때 물리 키를 누르면 **원본 이벤트와 해석 결과가 같은 줄에** 나타난다.
- [ ] 프리셋이 발화한 줄은 **어느 프리셋인지**를 이름으로 보여준다(`Layer` 만 보여주지 않는다).
- [ ] `Consume` 된 줄이 통과된 줄과 시각적으로 구분된다.
- [ ] 링이 넘치면 버려진 개수가 창에 표시된다.
- [ ] 창을 닫으면 계측이 멈춘다(`ULTRAKEY_TRACE_TAP` 로 따로 켜 두지 않은 한).
- [ ] ⭐ **뷰어에 관한 어떤 것도 탭 콜백에 락·할당·로깅·`emit` 을 더하지 않는다**(`architecture.md` §2.2 리뷰 체크리스트).

## 9. 미해결 질문

1. **개별 프리셋 라벨의 정확한 대응**. `RuleId::Preset(u8)` 의 숫자가 F-08 16종 중 어느 것인지는 `ultrakey-presets` 의 등록 순서가 정본이다. 이 대응이 바뀌면 뷰어의 표시도 함께 바뀌어야 한다 — 대응표를 한 곳(프리셋 크레이트)에 두고 뷰어가 그것을 읽는 형태로 두었으나, 대응이 깨졌을 때 그것을 잡아내는 테스트는 아직 없다.
2. **한 줄로 압축되지 않는 판정**. quick press 처럼 **키를 뗄 때** 비로소 결정되는 규칙은 down 줄과 up 줄 두 개로 나뉘어 보인다. 사용자가 그 둘을 연결해 읽을 수 있는지는 실사용 관찰이 필요하다.
3. **표시 문자열의 현지화 범위**. 지금은 규칙 이름만 카탈로그를 타고 나머지(`KeyDown`·`Pass`·`Consume`)는 영어 고정이다 — 이것들은 로그와 같은 성격의 기술 어휘라 번역하지 않는 편이 진단에 유리하다는 판단이나, 실사용 확인은 하지 않았다.

# F-19 · 언어별 프리셋 (Language Presets)

> **한 줄 요약** — Ultrakey 가 언어 설정을 제공하는 언어(`ko`·`ja`·`zh`; `es` 는 이번 판정에서 제외)별로 "체크박스 하나로 켜는" 사전 정의 입력·전환 프리셋을 제공한다. 설정 UI 는 **사이드바에 `언어` 상위 노드를 두고 하위에 언어별 탭을 펼치는 트리 구조**(이슈 #113 사용자 결정). 이 기능은 SuperKey 원본에 없고 F-16(한국어 입력)의 연장선에 선 **클론 고유 신설 기능**이다 — 1차 근거는 Karabiner-Elements 복합 변형 카탈로그의 규칙과 웹 검증([`../research/ke-complex-modifications-analysis.md`](../research/ke-complex-modifications-analysis.md))이다.
> **의존성** — `F-07`(key-remapping-engine)의 중재 엔진·정본 눌림 테이블·quick press 판정 위에서 동작하며, 새 이벤트 탭이나 새 중재 기구를 만들지 않는다. `F-14`(localization-and-input-sources)의 입력 소스 판정 API 를 재사용한다(F-16 §3.3 이 요구한 원본 소스 언어 노출 포함). `F-10` 의 최전면 앱 게이트, `F-16` §3.5 의 앱 제외 게이트 패턴을 재사용한다. `F-09`(preferences-ui)의 탭 구조·컨트롤 카탈로그·종속 표현 3종 규약을 따른다 — 단 사이드바 계층화 한 건만 이 명세에서 확장한다(§4.1). 저장은 `F-15` "부재 = 기본값" 규약을 따른다.
> **관련 명세** — 언어 노드 중 `ko` 는 `F-16`(korean-input.md)이 정본이다(§3.1). 중재 규칙표·엔진 규칙 ID 는 `F-07`·`../dev/architecture.md` §6.4. 갈라짐 정당화는 `README.md` "원본과 갈라지는 지점". 탭 아이콘·사이드바 규약은 `F-09`(preferences-ui.md) §3.1.
> **1차 근거** — [`../research/ke-complex-modifications-analysis.md`](../research/ke-complex-modifications-analysis.md) (이슈 #113 위임의 전수 분석·웹 검증). 이 문서의 판정 표(§5)가 이 명세 §3 의 정본이다.
> **상위 참조** — 갈라짐·기준 1~3·F-16/F-17 선례: `README.md`. canned preset 철학: `F-08` §1. F-16 참조·중재·앱 제외: `F-16` §3.1~§3.6·§4·§5 #13. UI 규약: `F-09` §3.1·§3.2·§3.8·§4. 입력 소스·로케일·endonym: `F-14` §3.1·§3.2. 저장·충돌: `F-15` §3.3·§3.4.

## 1. 개요

이 기능은 **언어별 프리셋**을 정의한다: Ultrakey 가 현지화를 제공하는 언어(`ko`·`ja`·`zh`·`es`, F-14) 중, 실제로 **입력 전환·문자 치환 프리셋이 가치 있는 언어**에 대해 사용자 언어 환경의 결함을 다루는 사전 정의 규칙 세트다. `es` 는 분석 결과 사용도 증거가 부족해 **이번 회차에서 프리셋을 제공하지 않는다**(§3.4).

**왜 원본에 없는 기능을 만드는가.** F-16 이 이미 같은 결정을 한 번 내렸다 — SuperKey 는 영어 단일(실측)이라 언어 입력 문제 자체가 원본에 없고, `README.md` 갈라짐 표 1행(F-16)이 "1차 근거는 한국어 macOS 사용자가 실제로 운용 중인 Karabiner 규칙 4종"으로 이 길을 열었다(2026-08-30, 이슈 #20). **F-19 는 그 갈라짐의 언어 확장이다** — 같은 종류의 새 갈라짐이지 새 종류의 갈라짐이 아니다. 현지화(F-14, D4·D6)로 5개 언어 UI 를 내놓기로 한 이상, 각 언어 사용자가 실제로 겪는 입력 환경의 결함을 다루는 것이 제품 논리로서 일관된다.

**F-08(canned preset) 정합성.** `power-user-presets.md` §1 의 철학 — "체크박스 하나로 켜는 사전 정의 규칙, 임의 커스텀 리매핑은 의도적으로 제공하지 않는다" — 을 그대로 지킨다. **하지만 F-19 는 F-08 의 확장이 아니라 F-16 계열의 연장선이다.** Presets 탭(F-08)은 손대지 않는다 — F-19 는 언어 입력 처리라는 관심사를 소유하고, 소유권 경계는 §3 에서 못박는다. 카탈로그의 패턴은 전수 이식하지 않고 **선별 후 하드코딩**한다(§8 부정형 기준).

**갈라짐 정당화 (README 갈라짐 기준 1~3):**

| 기준 | 판정 | 근거 |
| :--- | :--- | :--- |
| 1. 원본이 다루지 않는 문제 | ✅ 통과 | SuperKey 는 영어 단일(실측, F-14 §1)이라 언어 입력 전환·문자 치환 요구 자체가 원본에 없다. F-16 이 같은 기준으로 성립한 선례 |
| 2. macOS 가 이미 해결해 주지 않아야 | ✅ 통과 (기능 단위) + ⚠️ **패턴별 실측 의무** | macOS 는 입력 소스 전환 단축키(`⌃Space`)와 중국어 입력기의 캡스락 중/영 토글(네이티브, 실측 문건 §4-3)을 제공하지만, "두 손 위치에서 한/영 전환(윈도우 호환)", "英数/かな 토글", "₩↔백틱 치환", "JIS 를 US 처럼" 같은 물리 키 재배치 문제는 macOS 기본 설정으로 안 된다. **단 채택 패턴 각각에 네이티브 대체 수단이 없는지 실기기 확인을 §9 질문으로 부과한다** — 확인 전에는 채택해도 `(미확정)` |
| 3. 기존 명세의 규약 위에 선다 | ✅ 통과 — ⚠️ **사이드바 계층화만 우리 규약(F-09)과의 갈라짐** | F-07 엔진·F-14 입력 소스 API·F-15 저장·F-09 컨트롤 규약을 그대로 따른다. 트리(사이드바 계층화)가 F-09 §3.1 과 갈라지는 부분은 §4.1 에 **F-17 예외와 무관한 별도 근거**(이슈 #113 사용자 결정 + 정보 구조)로 기록한다 — README 기준 3 예외가 "다른 탭이 F-17 예외를 근거로 사이드바를 도입해서는 안 된다"고 못박았으므로, 이 계층화의 근거는 반드시 그 예외 밖에서 와야 한다 |

⭐ **기준 2 의 실측 의무는 이 명세의 핵심 품질 게이트다.** 연구 문건 §4-3 이 확인한 대로, 예컨대 Apple 중국어 입력기에는 캡스락 중/영 전환이 **네이티브 내장**이다 — zh 프리셋의 가치는 "제3자 입력기(搜狗 등) 한정"으로 좁혀진다. 채택 프리셋마다 §3 의 "네이티브 대체" 열에 실기기 판정을 남긴다.

## 2. 사용자 시나리오

### 시나리오 A — 한국어 사용자가 캡스락을 한/영으로 (F-19.1)

전제: 사용자가 `언어 ▸ 한국어` 노드에서 `캡스락 탭 = 한/영 전환`(F-19.1)을 켰고, 입력 소스는 ABC + 한국어 2-set 두 개다.

1. 사용자가 캡스락을 빠르게 탭한다.
2. F-07 이 quick press 로 판정한다(F-08.2 와 같은 기구).
3. F-19.1 이 캡스락 keyDown 을 소비하고 `space`+`control`(⌃Space) 재주입으로 치환한다 — macOS 가 "이전 입력 소스 선택" 단축키로 인식해 입력 소스를 전환한다(F-16.1 과 같은 출력 경로).
4. 캡스락을 **길게** 누르면(F-07 quick press 미판정) 캡스락 본래 기능(잠금)으로 동작한다 — `to_if_held_down` 의미론.

> ⭐ macOS 기본 캡스락 한/영과의 차이: 기본 동작은 전환에 **눈에 띄는 딜레이**가 있는 것으로 알려져 있고(연구 §4-1, 사용자 다수 증언), F-19.1 은 `⌃Space` 합성이므로 즉각적으로 전환한다. **단 macOS 한국어 입력기에 "캡스락 전환" 네이티브 옵션이 실재하는지 확인 전에는 `(미확정)`**(§9 #1).

### 시나리오 B — 윈도우 전환자가 오른쪽 command 로 한/영을 (F-19.2)

전제: 사용자가 `언어 ▸ 한국어` 노드에서 `오른쪽 command = 한/영 전환`(F-19.2)을 켰다.

1. 사용자가 오른쪽 command 를 아무 modifier 와 함께 누르지 않고 단독 탭한다.
2. F-19.2 의 "modifier 부재" 조건이 성립해 `space`+`control` 재주입으로 치환한다 — F-16.1 과 동일 출력.
3. Windows 의 한/영 키 위치(우측 Alt 부근)와 매칭되는 오른쪽 command 위치에서 손을 옮기지 않고 전환한다(연구 §4-1: 윈도우 전환자 실사용).

### 시나리오 C — JIS 키보드 사용자가 캡스락으로 英数/かな를 (F-19.3)

전제: 사용자가 일본어 JIS 키보드를 쓰고, `언어 ▸ 日本語` 노드에서 `캡스락 = 英数/かな 토글`을 켰다.

1. 사용자가 캡스락을 탭한다.
2. 현재 입력 소스가 일본어이면 `japanese_eisuu`(英数) 키 이벤트를, 일본어가 아니면 `japanese_kana`(かな) 키 이벤트를 합성해 방출한다(F-16 §3.2 의 keycode `0x66`/`0x68` 와 같은 물리 계열 — 중재는 §5).
3. 일본어 IME 가 그 키 이벤트를 받아 영/일 모드를 전환한다 — Karabiner 커뮤니티와 같은 동작(연구 §4-2, 등급 ①).

### 시나리오 D — JIS 키보드를 US 처럼 (F-19.6)

전제: JIS 키보드 사용자가 `언어 ▸ 日本語` 노드에서 `JIS 키보드를 US 배열처럼`(F-19.6)을 켰다.

1. 사용자가 `shift+2`(`"`) 를 누르면 JIS 배열대로 `@` 가 아니라 **US 배열대로 `"`** 가 입력된다.
2. F-19.6 은 실행 파일에 하드코딩된 18 개 심볼 치환표를 그대로 적용한다(조건 없음, 정적 1:1) — `key-remapping-engine.md` 계층 4 스타일이지만 언어 노드 소속이라 여기서 정의한다.
3. **사용자가 F-19.6 과 F-16.2(한/영 키)를 동시에 켜면** §5 의 키코드 공유 중재가 발동해 충돌 대화상자가 뜬다.

### 시나리오 E — 스페인어 사용자 (프리셋 없음)

스페인어 사용자가 `언어` 트리를 열면 `Español` 노드는 없다(§3.4 "추가 안 함"). 스페인어 입력의 dead keys 문제는 Ukelele 커스텀 레이아웃 등 카탈로그 밖 해법이 주류이고(연구 §4-4), 프리셋으로 제공할 패턴의 사용도가 검증되지 않았다. `es` 에 대한 판정 기록은 연구 문건 §5-4 와 이 명세 §9 에 남는다.

### 시나리오 F — RDP 클라이언트가 최전면일 때

전제: F-19 전환류 프리셋(F-19.1~F-19.4·F-19.7)이 켜져 있고, `원격 데스크톱 클라이언트에서 언어 키 처리 끄기`(F-16 §3.5 의 게이트 패턴을 언어 프리셋에도 적용)가 켜져 있다.

1. 원격 데스크톱 클라이언트가 최전면일 때 언어 전환 규칙은 평가되지 않는다.
2. 대상 시스템의 입력기가 원래 키를 받아 처리할 수 있다 — F-16 §3.5 의 근거(원격 세션에서는 대상 시스템 입력기가 처리해야 한다)와 같다.

### 3.4 스페인어 (es) — 추가 안 함 (이번 회차 판정)

- **판정**: 프리셋 제공 안 함. `Español` 노드도 만들지 않는다(§4.1 노드 존재 규칙).

- **사용자 원칙 적용**: "굳이 설정할만한 패턴이 없는데 추가할 이유는 없다"(이슈 #113).
- **재검토 여지**: §9 #5.

### 3.5 앱 제외 게이트 — F-16 §3.5 패턴 재사용

F-19 의 전환류 규칙(F-19.1~F-19.4·F-19.7)은 **F-16 §3.5 의 기능군 단위 기본 제외 목록 패턴을 그대로 재사용**한다 — "키 입력을 이 맥의 입력 스택이 아니라 다른 OS·다른 세션의 입력 스택으로 그대로 전달하는 앱(원격 데스크톱·VNC·VM 콘솔)". 대상 목록 편집 UI 는 F-16 이 이미 만든 가변 길이 목록 편집기를 공유한다(새 컨트롤 만들지 않음). 저장: `korean.excludedBundleIds` 의 형을 그대로 두되 언어별로 — §4.3 참조. ⚠️ F-19.6(JIS→US 심볼)은 **대상이 아니다**(타이핑 문자 문제지 입력 소스 전환 문제가 아님 — 원격에서도 JIS 키보드는 타이핑에 관여함) `(추정 — F-16 §3.5 의 선정 기준 해석)`.

### 3.6 F-05 hyper 소스 키와의 중재 (⭐ 결정)

F-19.2(오른쪽 command)·F-19.4(⌘ 단독)는 **modifier 키를 트리거로 쓴다** — hyper/meh/bleh 의 소스 키 팝업에 나오는 키들이다. 규칙:

- F-19.2·F-19.4 의 발화 조건에 "**이 키만 눌려 있고 그 외 어떤 modifier 도 없을 것**"이 이미 포함되어 있다. hyper 합성 flags 가 활성이면 조건이 깨지므로 발화하지 않는다 — F-16.1 의 hyper-shift 중재(F-16 §3.4)와 같은 결정론적 논리.
- **사용자가 같은 물리 키(예: right command)를 hyper 소스와 F-19.2 양쪽에 두면** 후자에 대한 안내 문구(F-16 §3.6 과 같은 형태: "동작하지 않는다면 hyper 소스와 겹치는지 확인")를 둔다. 조용한 실패가 아니라 안내다.

| ④ `Presets` 탭 안 언어 섹션 | README F-16 기각 대안 ①과 같은 근거 — 성격이 다른 항목이 섞이고 Presets 탭은 이미 가장 크다 |

### 4.2 종속 표현 3종의 적용

| 유형 | 이 기능에서의 사례 |
| :--- | :--- |
| **① 비활성화(dimmed)** | `언어 ▸ 中文` 노드의 `캡스락 = 중/영 전환` 부제에 "Apple 중국어 입력기에는 내장된 캡스락 전환이 있어, 제3자 입력기를 쓸 때 유효합니다" 를 부제 텍스트로 둔다(설정 조작 자체는 유효) |

### 4.3 저장 키 — F-15 규약 + 기존 네임스페이스 정합

- **전부 "부재 = 기본값(☐)"** — 새 키는 기본값이 ☐ 이므로 일반 규약이 그대로 성립한다(F-16 §4.2 의 "기본 ☑ 반전" 주의는 이 명세에 해당 없다).
- 네임스페이스: 기존 `korean.*` 을 잇는 언어별 접두 — `japanese.*`·`chinese.*`. F-19.1·F-19.2 는 ko 노드 소속이므로 `korean.capsLock…`·`korean.rightCommand…` 로 **`korean.*` 네임스페이스를 확장**한다(정의는 이 명세 — §3.0).
- 앱 제외 목록(§3.5): `korean.excludedBundleIds` 형을 따른다 → `japanese.excludedBundleIds`·`chinese.excludedBundleIds`(`Vec<String>`, 부재 = 기본 목록, 존재 시 완전 대체).
- export/import(F-15 §3.4)·충돌 감지(F-15 §3.3)는 언어별 키도 동일 취급 — 새 기구 없음.

### 4.4 i18n — 5 카탈로그 등재 의무 (⭐ 구현 시 깨지면 안 되는 게이트)

- 새 문자열은 전부 **5 개 카탈로그**(`resources/i18n/{en,ko,es,ja,zh}.json`, 실측 267 키 parity)에 등재한다 — 탭 라벨(`settings.tab.language` 등)·자식 라벨·프리셋 라벨·부제.
- 접두 규약: F-16 §4.2 정정 선례대로 **`settings.<탭>.<항목>`** — `settings.korean.caps_lock`·`settings.japanese.*`·`settings.chinese.*`. ⛔ `settings.` 로 시작하는 리터럴은 `frontend_wiring.rs` 자동 검사가 카탈로그 동등을 강제한다(누락하면 빌드-테스트 실패). 그 자동 검사를 우회하지 않는다.
- `es` 노드가 없다고 es 카탈로그에 문자열이 빠지는 것이 아니다 — **부모 `언어` 라벨·공통 안내는 5 카탈로그 전부**에 들어간다(4.1 표의 번역 열).

## 7. 구현 접근

**판정: `Rust 바인딩`.** 새 API 가 없고 기존 FFI 를 재사용한다(README 구현 접근 3분류). F-16 과 같은 계층 3/4 배치이고, 새 이벤트 탭·새 중재 기구·새 출력 경로를 만들지 않는다.

- **규칙 ID**: `../dev/architecture.md` §6.4 의 규칙 ID 체계를 이어 **P17~P23** 을 F-19 규칙 7 종(F-19.1~F-19.7)에 배정한다(평가 순서를 ID 로 고정하는 기존 규약). F-16 의 P13~P16 과 충돌하지 않는다.
- **구현 단계**: F-19 규칙 전부가 F-16 이 이미 만든 출력 경로(⌃Space 재주입)·quick press 기구·앱 제외 게이트 위에 얹히므로 **F-16 구현(M2 3차) 완료가 선행 조건**이다. 물리 키(keycode) 사실은 전부 확정되어 있다(연구 문건 + F-16 §3.2). 실기기 확인이 필요한 것은 macOS 네이티브 대체 수단(§9 #1~#4)이다.
- **트리 구조**: 사이드바 계층화는 `settings.html` 의 탭 목록·`main.rs` 의 `KNOWN_TABS`·`settings_set_tab` 배선의 확장. `ui.lastTab` WHITELIST 에 자식 탭만 추가하고 부모는 tab 이 아님(§4.1).

## 8. 수용 기준

- [ ] `언어` 사이드바 노드가 펼침/접힘 되고, 자식 탭(`한국어`·`일본어`·`중국어` — ko 로케일 표기, 각 로케일 언어로 번역)이 실제 탭으로 동작한다(`KNOWN_TABS` 갱신·`ui.lastTab` 보존).
- [ ] **축퇴 사례 무결성**: `korean.capsLockSwitchesInputSource` 등 F-19 키가 전부 ☐(부재) 기본값이고, 파일에 아무 키도 생기지 않는다.
- [ ] F-19.1: 캡스락을 1초 내 탭하면 `space`+`control` 이 방출되고(입력 소스 전환), 길게 누르면 캡스락 본래 동작.
- [ ] F-19.2: 오른쪽 command 단독 탭 시 `space`+`control` 방출, **`hyper`+오른쪽 command 구성에서는 발화하지 않는다**(§3.6).
- [ ] F-19.3: 일본어 입력 소스에서 캡스락 탭 시 `japanese_eisuu` 가, 비일본어 소스에서 `japanese_kana` 가 방출된다.
- [ ] F-19.4: 좌⌘ 단독 탭 시 `japanese_eisuu`(0x66), 우⌘ 단독 탭 시 `japanese_kana`(0x68) 가 방출되고, ⌘+W 조합은 홀드로 확정돼 modifier 로 남는다(안 A).
- [ ] F-19.5: JIS 에서 `international3` 단독 → `⌥international3` 합성. ⛔ **`international3 → \` 직접 매핑이 존재하지 않는다** — `]` 함정 방지.
- [ ] F-19.6: JIS 키보드에서 §3.2.1 표 20행대로 심볼이 US 배열로 입력된다.
- [ ] F-19.7: 캡스락 탭 시 `space`+`control` 방출(중/영 전환).
- [ ] **CJK 직접 전환 금지**: 코드에서 `select_input_source` 류 구현(또는 `TISSelectInputSource` 직접 호출)이 **존재하지 않는다**(부정형 — 연구 §4-1 버그 근거).
- [ ] **외부 규칙 파일 불러오기 기구 금지**: KE 카탈로그 JSON 을 읽어 규칙을 만드는 임포트 경로(런타임·빌드 타임 모두)가 **존재하지 않는다** — 프리셋은 전부 하드코딩된 열거다(F-08 §1 경계 · AGENTS.md §4 제품 제약).
- [ ] ⭐ **§5 #1 확정 pair 세트 충돌**: (i) F-19.1 과 F-19.3(또는 F-19.7)을 동시에 켜려 하면, (ii) F-08.2(quick press caps lock)가 켜진 상태에서 F-19.1/3/7 을 켜려 하면, (iii) F-19.2 와 F-19.4(우⌘)를 동시에, (iv) F-19.5 와 F-19.6(JIS) 을 동시에 켜려 하면 **F-15 충돌 대화상자**가 뜨고, 사용자 선택이 저장된다(§5 #1). ⛔ 기존 문구("F-16.2+ F-19.6")는 사실 오류라 교체.
- [ ] RDP·VNC 클라이언트가 최전면일 때 F-19 전환류가 통과되고(F-16 §3.5 게이트), 같은 상태에서 hyper 는 계속 동작한다.
- [ ] 새 문자열 전부가 5 개 카탈로그(`en·ko·es·ja·zh`)에 존재하고 `settings.*` 접두를 따른다 — `frontend_wiring.rs` 자동 검사 통과.
- [ ] 로그 문자열은 전부 영어(§3.1.6 규약 — F-14) — 새 로그가 추가되면 영어 리터럴.

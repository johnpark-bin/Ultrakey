## 0. 요약 — 실측 결론 (리뷰 확정 전 초안)

**① 사용자의 실 설정 전량을 재현해 봐도, 중재 코어(`Arbiter`)는 인풋 박스 ⇧+Space 를
1번째 탭부터 F-16.1 로 발화한다 — "3번째에만 동작"은 중재 계층의 탭 간 상태로 설명되지
않는다**(T-121-1 ~ T-121-3, 실측).

**② 사용자 설정에서 의심 후보(F-08 shift 추적 가설)는 기각**: `is_tracked`(
`arbitration.rs:564-569`)는 **세션 게이트(:483-548) 뒤**라, 인풋 박스 세션 중에는 shift
이벤트가 `handle_tracked_key_event`(FSM)에 도달할 수 없다. 사용자 설정의 F-08.8(double tap
shift)·F-08.11(quick press shift)은 **꺼져 있고**(U10·U11), F-08.9(좌우 shift=캡스락)·F-08.10
(shift+캡스락)은 **켜져 있지만**(U7·U8) — 둘 다 트리거 판정이 "양쪽 shift 동시"·"shift+캡스락"에
한정되어 단독 ⇧+Space 를 삼키지 않는다(F4).

**③ 엔진 합성 재주입·마커도 전수 확인 결과 무죄** — 모든 합성 이벤트는 `ULTRAKEY_MAGIC`
마커를 심고, 콜백 트램폴린 0-a 단계(`event_tap.rs:334-342`)가 엔진 호출 **전에** 통과시켜
합성 이벤트가 arbitration 을 다시 타는 경로 자체가 없다(F10·F11).

**④ 그래서 "3번째에만 동작"의 최종 매커니즘은 `(미확정)`** — 남는 후보는 탭 스레드 런타임
상태·이벤트 드롭 레이스(후보 E: Arbiter 눌림 테이블·래치의 세션 간 생존 + 이벤트 유실)와
웹뷰 IME·시스템 hotkey 계층(후보 B·C)뿐이다. 세션(CLI·무권한)에서 그 계층은 측정 불가 —
실기기 절차(M1~M9, 트레이스·눌림 테이블 덤프 기반)로 넘긴다.

**⑤ 이 PR 의 내용**: ㉠ **트레이스 계측 확장**(진단 전용 — `TapTrace` 에 ⌃⌥⌘ 눌림
스냅샷 + 합성 hyper 활성 비트 추가, 런타임 동작 무변경), ㉡ **사용자 실 설정 전량 재현
재발 방지 테스트 5종**(T-121 시리즈 — 기존 T-118 이 커버하지 않았던 "F-16.1 + F-08 프리셋
+ hyper + D-1 동시 로드" 구성 + 세션 열림 직전 첫 탭 + stale modifier 특성화), ㉢ 실측
문서(본 문서) + 명세 결정 기록, ㉣ PR 본문에 실기기 검증 절차(확장된 트레이스 필드
규격 포함). **새 기구·새 레이어·새 FSM 금지** — 기존 구조만.

## 3. 원인 판정 (초안 — 리뷰 확정 전)

### 확정된 것

> **"⇧+Space 가 1·2번째 탭에 소비되어 3번째에만 통과한다"는 중재 계층·머신·엔진 합성
> 경로의 매커니즘은 존재하지 않는다 — 사용자 실 설정 전량 재현 테스트가 1번째 탭부터
> 발화함을 고정하고(F6), 머신은 탭 간 상태가 없으며(F8), 합성 이벤트 재중재는 마커가
> 구조적으로 차단한다(F10·F11).**

**"여러 설정 상호작용"이 원인이라는 이슈 추정은 중재 계층에서 기각**된다:
- shift 를 FSM 추적 키로 만드는 규칙(F-08.8/11)은 **꺼져 있음**(F3).
- 켜진 shift 관여 규칙(F-08.9/10)의 트리거 조건은 단독 ⇧+Space 와 만나지 않음(F4).
- 세션 중 FSM 도달 자체가 구조적으로 불가(F5).
- hyper(우⌘)·F-19(전부 꺼짐 — 설정 키 부재)·D-1(캡스락 alias·⌘↔⌥ 리매핑)은 ⇧+Space

## 4. 수정 방향 (초안 — 리뷰 확정 전)

### 현재 코드 상태

인풋 박스 세션 중 ⇧+Space 는 **이미** 1번째 탭부터 D2(F-16.1 재평가)가 발화한다(§2-2).
위임 계약이 제시한 "시나리오 A(세션 중 shift-소스 규칙의 FSM 추적 배제)"는 **이미
구조적으로 성립**한다(세션 게이트 > `is_tracked`, F5) — 새로 만들 것이 없다. "결정론적
우선순위"도 인풋 박스 분기에서 D2 가 D1·통과 판정보다 먼저 평가되는 것으로 이미 성립한다.
"1회 탭으로 전환"이라는 수용 기준은 **중재 계층에서 이미 충족**되어 있고, T-121 시리즈가
그것을 사용자 실 설정 전량으로 고정한다.

### 그래서 수정의 내용 (후보 — 리뷰 확정 대상)

| 후보 | 내용 | 채택 여부 |
| :--- | :--- | :--- |
| ① **중재·엔진 판정 로직 변경 제로** + T-121 재발 방지 테스트(사용자 실 설정 전량) + 실기기 절차 보강 | #120 과 같은 성격 — 다만 이번에는 **사용자 실 설정을 직접 재현**해 1번째 탭 발화를 고정하고, 1·2번째 탭이 사라지는 런타임 계층은 (E)/(B)/(C)/(D) 후보를 M-절차로 소거한다 | ⭐ **확정 초안** — 실측이 "중재 계층에 고칠 것이 없다"는 것을 재현으로 입증(F6·F11) |
| ② **트레이스 계측 필드 확장만 허용** (유일한 프로덕션 변경) | `TapTrace` 에 ⌃⌥⌘ 6비트 눌림 스냅샷 + `active_synth_flags` 비활성 비트 추가(진단 전용·POD·`should_trace` 게이트 안 — 새 탭/레이어/FSM 아님, 동작 무변경). 근거: 실기기 M4 가 후보 (E)의 두 차단 메커니즘(stale ⌘/⌥/⌃·hyper 슬롯 잔류)을 **판정**하려면 이 필드가 필요하다(상급 리뷰 1번 결정) | ✅ **포함 — 구현 완료** |
| ③ 새 기구·새 이벤트 탭·새 FSM·`select_input_source` 직접 호출 | 위임 계약 ⛔ | ❌ 금지 |
| ④ D2 발화 조건에 "탭 카운트" 등 새 상태 추가 | 새 상태는 새 기구 금지 위배 + 중재가 이미 1회 발화하는데 더할 것이 없음 | ❌ 기각 |

⭐ **수용 기준(§7)**: "인풋 박스 세션 중 ⇧+Space **1회 탭**으로 전환"은 **T-121-1 의
단언**(⇧+Space 1회 탭이 ⌃Space 치환을 정확히 1회 방출 — 소비·누락 없음, 반복 탭도 매번
동일)으로 고정한다. 실기기 1회 탭 확인은 M1 이 맡는다(M-절차).

> 불변식(락·힙 할당·동기 로깅 없음 — `trace.rs` 모듈 문서) 유지. 엔진 측 새 공개 접근자
> `Arbiter::active_synth_flags` 는 `is_pressed`(#108 계측 전용)와 같은 패턴이다.

# 이슈 #88 — 설정 창을 닫았다 다시 열면 열리지 않는다 (창 파괴 후 재생성 부재) — 계획 초안

> 저장 위치: `docs/plan/issue-88-settings-window-hide-on-close.md`
> 상태: **초안(중급) — 상급 리뷰 대기**
> 결론부터: **옵션 A(닫기→숨김, 창 상시 유지)를 권장한다.** 재생성(builder)은 기각.

---

## 1. 요약

설정 창은 `tauri.conf.json` `app.windows` 에 `visible:false` 로 정적으로 선언되어 부팅 시 생성된다. 이 창은 `CloseRequested` 핸들러가 없어 **사용자가 창을 닫으면(빨간 stoplight, `⌘W`) 파괴**되며, `show_settings_window`(main.rs:4692)와 #68 재실행 신호(5430)가 공통으로 타는 `on_main_thread` 헬퍼(4646)는 `get_webview_window("settings")` 이 `None` 이면 **에러 로그만 남기고 끝**낸다(4662-4664). 재생성 로직이 없어 "닫았다가 다시 열 수 없는" 세 증상(설정, About, 앱 재실행)이 모두 발생한다.

이 계획은 **닫기를 파괴가 아니라 숨김으로 전환**한다(옵션 A). 창 상주 시 ① 재생성 코드 불필요 ② 크기 영속 배선(`wire_window_size_persistence` → `on_settings_window_resized`)이 살아있는 그대로 유효 ③ #68 경로가 별도 수정 없이 해결된다.

**확정된 사실(코드 실측)**:
- 설정 창: 정적 선언(tauri.conf.json:22-31, `label: "settings"`, `visible:false`), 런타임 builder 없음.
- settings 창에 `CloseRequested` 핸들러 없음(Event Viewer 에만 2820).
- `show_settings_window`(4692-4707) — 창이 존재하기만 하면 재열림 로직 완전. **문제는 창이 파괴됐을 때뿐.**
- `ExitRequested`(4262-4273): 암묵적 종료 요청에 `prevent_exit()` — 앱은 살고 창만 죽는 구조.
- `wire_window_size_persistence`(4841-4894): setup()(4195) 1회만 호출. 파괴·재생성 시 전부 재배선 필요 — **옵션 B 의 본전 비용.**
- About 메뉴는 현재 설정 창 열기로 구현(main.rs:5292) — 피드백 2번도 같은 근본 원인. 독립 About 창은 #87 소관.

## 2. 결정 목록

### D1 — 창 정책: 닫기 → 숨김(hide), 창 상시 유지 (옵션 A) ⭐ 핵심

닫기 시 `CloseRequested` 에서 `api.prevent_close()` + `hide()`.

근거:
1. **재생성 코드가 원천적으로 불필요** — show_settings_window 재열림 로직(4699-4705)이 창 존재만 전제. None 분기 도달이 사라진다.
2. **크기 영속 배선이 그대로 살아있음** — 파괴-재생성은 배선 재설치·크기 복원·`last_applied_window_size` 재세팅이 필요(옵션 B 비용). A 는 무변경.
3. **탭·스크롤 JS 상태 유지** — 상주 시 닫았다 열어도 그대로.
4. **저장소 관례 일치** — Seek 오버레이도 "재생성 비용 회피 상주" 정책(seek-overlay-ui.md §3.1).
5. **회귀 최소** — 새 핸들러 하나 배선 + 주석 갱신뿐.

**기각: 옵션 B (destroy + builder 재생성)**
- Event Viewer 패턴(2800-2816)은 부수 동작(계측 종료)이 있는 창이라 이식에 재설계 필요.
- 닫기 직후 400ms 디바운스 창 안 크기 변경 손실 가능(저장은 디바운스 스레드가 400ms 후).
- 재생성 시 `wire_window_size_persistence` 재호출 → 디바운스 스레드 중복 스폰 버그 유발 쉬운 구조.

**기각: B-변형(일정 시간 후 자동 숨김)** — 복잡도만 증가.

### D2 — 구현 위치: `wire_settings_window_lifecycle(&handle)` 신설

`setup()` 에서 `wire_window_size_persistence`(4195) 옆에 호출. 내부: `get_webview_window("settings")` → `Some` 이면 `window.on_window_event(CloseRequested → prevent_close + hide)`. `None` 이면 `tracing::error`(기존 None 분기 4890-4893 같은 처우). settings.html 프런트 변경 없음.

### D3 — 크기 영속: 무변경

창 상주로 기존 배선 그대로 유효. `is_visible()==Ok(true)` 가드(4912)와 hide 중 리사이즈 충돌 없음. show 는 크기 변경 안 함.

### D4 — 이슈 #68(앱 재실행 → 설정 창): **같은 수정으로 해결, 별도 작업 없음**

#68 경로(`setup_show_settings_observer` 5427-5435 → `show_settings_window`) — 옵션 A 에서 창 상시 존재 → 항상 동작. #68 검증은 이 이슈 수동 테스트 M4 로 포함.

### D5 — About(#87)와 공통 정책: 이 이슈는 명세에 "하나의 원칙"만 기록

- 이 이슈는 About 창을 만들지 않는다. 현행(ABOUT → 설정 창 열기) 유지 + D1 상주로 "About 클릭 → 설정 창 열림" 복구.
- #87 을 위한 공통 정책 문구를 명세에 남긴다: "메뉴가 여는 주 창(설정)은 닫아도 **숨김 유지(상주)**. About 등 신설 창의 정책은 별도 결정하되 상주를 기본값으로 검토."

### D6 — i18n: 불필요

사용자 노출 문자열 0개. 카탈로그 변경 없음.

### D7 — 권한 모달(permissions) 창은 스코프 밖

같은 구조라 잠재 결함 있으나, 사용자 피드백에 없으므로 제외. 동일 상주 정책 적용을 후속 이슈 후보로 기록.

## 5. 명세 갱신 초안 (`docs/spec/preferences-ui.md`)

**§3.3 "창 생명주기 — 닫기" 교체 초안:**

> - **닫기**: ⭐ **이슈 #88 로 실측 확정(2026-09-02) — 닫으면 숨긴다(파괴하지 않는다).** `CloseRequested` 에서 `prevent_close()` + `hide()`. 설정 창 인스턴스는 앱 종료까지 상주.
>   - 근거: `show_settings_window` 가 창 존재를 전제 — 파괴-재생성 경로 대신 상주가 최소 변경. 크기 영속 배선이 setup() 1회 배선이라 파괴 시 재설치 필요. Seek 오버레이 상주 관례(F-03 §3.1)와 일치.
>   - **기각: 파괴 후 재생성** — 배선 재설치·디바운스 스레드 중복 방지 재설계·닫기 직후 400ms 크기 손실.
>   - **공통 정책(#87 참조)**: 주 창 상주 원칙. 신설 창 정책은 해당 작업이 결정하되 상주 기본값 검토.
> - **다중 인스턴스 방지**: `(추정)` → **해소.** "이미 보이면 포커스만"(main.rs:4699-4703). 두 번째 인스턴스 재실행 신호(#68)도 같은 함수 — 숨김 상태 show, 표시 상태 포커스.

**§8 수용 기준 1행:**

> - [ ] 설정 창을 닫았다(빨간 버튼 또는 `⌘W`) 다시 열면(메뉴 Settings…, About, #68 앱 재실행) 정상적으로 다시 열린다. (이슈 #88)
